Updated: 2026-10-24

## Scope and counts

The current tracked source diff is **176 modified files, 21,246 additions, and 16,907 deletions**. With whitespace ignored, it is **19,929 additions and 15,590 deletions**. No tracked source files are deleted. Untracked additions are excluded from these totals. These counts include executable logic, data tables, comments, and UI text; they are not a measure of behavior parity. This is a substantial code reduction even though the net source diff is **+4,339 lines**.

This review checks the largest reductions and known workflows against the prior implementation. It is a partial semantic review, not approval that all prior behavior remains equivalent.

### Process flowsheet solver audit

- The baseline's auto-created streams and default stream, splitter, compressor, valve, and flash settings were removed; the cryogenic loading routine's fixed propellant properties and unsupported NASA/HYSYS labels now return unavailable.
- Mixer, splitter, flash, compressor, valve, recycle detection, and Wegstein calculation paths remain. Explicit-input tests cover mixer composition/flow/temperature/pressure, splitter conservation, compressor temperature, valve temperature/pressure, and the recycle loop.
- Added finite/physical output checks after each operation. If an operation overflows or otherwise creates an invalid stream state, the solver returns `NUMERICAL_FAILURE` and restores the pre-solve stream states. These checks do not independently validate the thermodynamic or unit-operation models.
- Added JSDoc types and `// @ts-check` for this production module; `npm run typecheck` now checks its inputs, stream states, and unit-operation handling. Project-wide `checkJs` remains false, so other JavaScript files are not checked by TypeScript yet.

### Engineering BOM workflow audit

The caller-input eBOM path retains hierarchy normalization, per-assembly mass and cost roll-up, indented rows, flattened part consolidation, and CSV export. The current renderer accepts an explicit hierarchy and the route retains an explicit legacy-field adapter. Missing numeric fields no longer receive fabricated defaults; the hierarchy rejects cycles, depths over 64, more than 10,000 nodes, unknown fields, and non-finite or nonphysical quantities, mass, and cost. CSV text fields are quoted and formula-leading values are escaped. No supplier, material, or price source is bundled, and every output remains experimental.

The route now keeps `rolledUp` as the per-one-root-assembly result and adds `requestedTotals`, which applies the root quantity to mass, cost, and leaf-part count. Child quantities remain per parent; the flattened view applies all parent quantities and the requested root quantity. Flattened lines consolidate only when part number, revision, name, material, supplier, unit mass, and unit cost all match. Revision is retained in flattened results and appended to CSV so the existing CSV columns keep their positions. The renderer clears stale results on input changes, ignores late responses for superseded inputs, and labels per-item versus extended columns. Numeric overflow returns `NUMERICAL_FAILURE`.

The UI explicitly says that roll-up totals include supplied mass/cost at every hierarchy node while the flattened view contains leaf rows only. All values remain caller-supplied, experimental, and unverified; the ordering contract is characterized with distinct revisions/suppliers and a root quantity greater than one, not independently validated as a procurement or mass model.

### CAD revision comparison audit

The prior CAD comparison loaded bundled synthetic revisions, selected implicit thresholds, and presented centroid displacement as a wall-thickness reduction. The current workbench has no preloaded revisions and does not run on open. It requires two caller-supplied revision objects, explicit `mm`/`mm3` units, and explicit tolerance and modification thresholds. Each revision is limited to 10,000 faces, the pairwise comparison to 10 million candidate pairs, and each renderer JSON field to 1 MB. Stable persistent face IDs are reserved across both revisions before unmatched faces use one-to-one nearest-centroid matching.

The result is an experimental centroid heuristic plus arithmetic over caller-supplied volumes. The legacy route and field aliases remain only with explicit units; `maxThicknessReductionMm` remains `null` for response-shape compatibility. No B-rep topology, wall thickness, material, manufacturing change, or structural integrity is assessed. The UI clears old results when inputs change, ignores late responses, and renders caller text with `textContent`. Focused engine and UI characterization cover required fields, units, limits, legacy aliases, stale-result handling, and persistent-ID precedence; this does not establish CAD geometry accuracy or full workbench parity.

### Engineering evidence report audit

The fabricated multi-domain certification report was removed. Generation now requires an explicit project identity/revision and engine version, non-empty dependency-version maps, hashed and unit-tagged input records, explicit assumptions and warnings arrays, and results tied to the same project revision with engine/backend/dependency versions, units, linked input hashes, warnings, and convergence diagnostics (or an explicit reason diagnostics do not apply). It rejects result hashes not linked to supplied inputs, mismatched revisions, missing provenance or diagnostics, non-serializable evidence, and evidence above 1 MB. Maturity is derived from the registry rather than caller claims, and HTML is escaped. Hash strings remain caller-supplied and are not recomputed from artifact bytes.

The report route still has no project-evidence producer: the renderer passes window.omniProjectEvidence or an empty object, and no current code assigns that global. The menu therefore shows the documented unavailable state in the ordinary application flow. The report iframe now has an empty sandbox attribute so its document has no script, form, or same-origin privileges. The contract does not provide project persistence or a validated evidence workflow.

### Renderer text-injection review

User-entered assistant messages and command-palette empty-state text are rendered as text. Assistant responses preserve only `strong`, `em`, `code`, and `br` formatting through a DOM builder; suggestion buttons are constructed with event listeners rather than inline handlers. Caller-input drop estimates and wizard summaries/details use text nodes, as do provider node names and telemetry values, sample catalog fields, viewport raycast metadata, and geometry-healer output. AI parameter edits use an explicit key/type/range allow-list, and consumer inspector values are bounded before template rendering. Drafting labels are escaped in generated SVG, and the renderer previews that SVG as an image data URL. A configured provider can no longer trigger a prefilled FEA dispatch: the UI keeps job submission disabled until an explicit request workflow exists. Other renderer templates use source-owned structure or numerical solver outputs, but broad renderer behavior and the remaining templates still need review.

### Controls block-diagram workflow audit

The prior Simulink panel was left as an empty, disabled canvas after removing a fixed drone/thermal diagram and a generated scope trace. The canvas and a caller-supplied `BlockDiagramGraph` engine already existed, so the UI now accepts JSON graph input and explicit duration/time-step fields, then invokes that engine through the existing preload method. It plots only solver samples returned for caller-supplied scope blocks; the fixed presets and continuous animation remain unavailable.

The exposed graph contract declares dimensionless signals, seconds for duration and step, seconds for step-source time and PID integral state, hertz for sine-source frequency, and explicit PID gain/limit units. Canvas positions use pixels. Source, gain, sum, PID, and scope blocks are supported for acyclic graphs. The generic integrator remains in the core engine but is rejected by the renderer and IPC adapter until per-port units can express its input/output dimensions. Feedback cycles are rejected because the current engine does not solve them.

The engine now evaluates dependencies in topological order instead of relying on block position, preserves time and signal precision, returns a numerical failure for non-finite state/output, uses repeatable generated IDs, and enforces total work/result-size limits. These changes improve input handling and reproducibility; they do not validate a physical control model, establish timing performance, or satisfy the later isolated-job requirement. The focused UI characterization passed **48/48**, the phase-5 UI checks passed **6/6**, and the Node 22.22.3 `npm test` run passed **434/434 smoke assertions**, with **9 validation cases unavailable** and **0 failed**.
